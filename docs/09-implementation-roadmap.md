| M3 | 长篇连续性与追读力 | M2 稳定 | 事件/图表可回到证据，规则经样本校准 | 6-9 |

| M5 | 自动采集、更多题材、向量增强 | 合规与真实需求 | 独立立项/指标/授权 | 单独估算 |

M0-M2 基础工作量约 19-28 人日，加 20% 风险缓冲约 23-34 人日。M0-M4 合计约 32-48 人日，加缓冲约 39-58 人日。与旧方案估算口径不同，本版明确把跨进程锁、读一致性、故障恢复、全部写入口和迁移测试计入范围。

估算假设：一名熟悉 TypeScript/Node 的主开发持续参与，前端/测试可配合，现有基础测试没有大面积失效。模型选型、复杂许可问题、未知存量数据损坏和发布审批不包含在该时间承诺中。M0 完成后按实际基线重新估算。

## 3. M0：工程、安全与品牌

| 任务 | 修改范围/输出 | 验收 |
| --- | --- | --- |
| M0-01 固定基线 | 记录三库 SHA、Node/pnpm、锁文件、许可证 | 来源可复现，不修改参考库 |
| M0-02 构建回归 | 安装、build、typecheck、test，记录原有失败 | 不把上游失败混写成新功能已通过 |
| M0-03 写入入口清单 | Runner/Writer/StateManager/API/CLI/Agent/daemon/import/repair | 每个正式写调用有归属和后续测试 |
| M0-04 网络边界 | loopback 绑定、Host/Origin/CORS/会话保护 | 非授权写入被拒绝，不对公网裸露 |
| M0-05 品牌改造 | title、Sidebar、App、错误包装、关于及资产 | Novel Creation 显示完整，兼容项保持 |
| M0-06 运行脚本 | Windows 跨平台启动/停止、显式 projectRoot、PID/端口 | 从根目录发起，试点不写正式目录 |
| M0-07 备份与文档 | 运行产物忽略、白名单备份、异地策略、恢复演练 | 恢复目录可读取，密钥不进入 Git |

M0 不接入新的正文生成策略。先获得可回归的宿主，再改变核心生产流程。

## 4. M1：只读整合

| 任务 | 产物 | 验收 |
| --- | --- | --- |
| M1-01 资产清单 | 来源、哈希、许可、题材/阶段标签、链接映射 | 不扫描 entire other，不丢相对引用 |
| M1-02 统一报告 schema | ResearchReport、Finding、Usage、ContextManifest | 前后端共享 Zod，错误可表达 |
| M1-03 Oh Story 分析/审核 | 长篇拆书、review、deslop 适配器 | 无 shell 注入、输出限额、只读证明 |
| M1-04 模板试点 | 2-3 个代表题材，人工标注样本 | 输出证据准确，误报有记录 |
| M1-05 UI 接入 | 研究列表、报告、规则筛选、模型用量 | 异步隔离、失败不丢原始材料 |
| M1-06 合同映射评审 | Python 合同/commit schema 对照与 fixtures | 明确哪些字段采用、转换或延后 |

M1 可以让作者使用分析与建议，但不得因为报告“通过”就写入正式正文和 truth。

## 5. M2：章节治理 MVP

M2 是安全闭环，不只是一页“审核后提交”的前端演示。

| 任务 | 核心改动 | 必需测试 |
| --- | --- | --- |
| M2-01 数据 schema | Draft/PlanApproval/Contract/Review/Commit/Journal | Zod、版本、JSON round-trip、哈希 |
| M2-02 候选持久化 | Writer/Runner 生成与修订写入候选区 | 生成/自动保存后正式状态不变 |
| M2-03 合同与失效 | `.plan.md` 批准、依赖/策略指纹 | 缺细纲、损坏、修订、HEAD 前进 |
| M2-04 审查流水线 | 宿主审计 + 履约 + 消歧 + 风格 | 证据定位、误报处理、修订上限 |
| M2-05 持久任务 | task-store 演进、幂等、取消、重启 | 202 后崩溃、重复请求、未知模型结果 |
| M2-06 提交与读取 | before/after、journal、HEAD、快照解析 | kill 注入、多文件失败、一致读 |
| M2-07 跨进程协调 | CLI/Studio 同书锁、租约与恢复 | 双进程竞争、旧拥有者不可继续发布 |
| M2-08 统一全部入口 | CLI/TUI/API/Agent/daemon/import/repair 转发/拒绝 | 治理书不能 fallback 旧写入 |
| M2-09 前端闭环 | 候选编辑、版本差异、审核、确认、回执 | IME、乱序响应、刷新、移动端 |
| M2-10 索引与恢复 | 投影游标、重建、最新章 revert | 索引失败不撤销提交，恢复幂等 |
| M2-11 导入/导出最小闭环 | 新书导入候选、HEAD 固定导出 | 不绕过治理，不导出半提交状态 |

建议关键路径：schema -> 候选 -> 合同/审核 -> 持久任务 -> 提交/恢复 -> 全入口接入 -> UI 和发布验收。前端可基于真实 schema fixture 提前并行，但最终联调不能只用成功 mock。

M2 首批仅新书及少量授权样本。手写候选同样可走审核/提交；最新章之外的历史编辑明确拒绝或只允许另存候选，不伪装成已经完成历史修复。

## 6. M3：长篇运营与质量

- 增加统一实体别名、时间线、角色状态和证据检索。
- 将 introduced/advanced/fulfilled/deferred/abandoned 承诺变更纳入 acceptedEvents。
- 在 Analytics 展示承诺、伏笔、节奏和情绪趋势，提供表格替代与正文跳转。
- 加入手动榜单导入、题材对比和样本化质量评估；不默认开启浏览器采集。
- 扩展合同中的题材策略但保持可选，校准后再将少数规则升级为 enforce。
- 建立长期投影重建、归档读取、千章规模性能与预算监控。

退出门禁：所有建议可说明来源；未确认模型判断不进入正式事实；统计重算不修改历史正文。

## 7. M4：存量与历史能力

- 对旧书生成预检与迁移报告，建立全量 genesis 基线，保留 imported_baseline 标记。
- 提供隔离工作区中历史章节改写、受影响链分析、逐章重审和受控切换。
- 同一事务/提交模型支持短篇，精简合同，不复制另一套状态管理。
- 执行真实副本迁移、版本升级/回退、密钥隔离和灾难恢复演练。
- 明确旧剧本、世界、翻译等功能兼容范围，防止未适配入口写入治理小说的数据。

退出门禁：至少一个真实授权长篇副本和一个短篇完成全流程；批量迁移结果可比较、可放弃，原始目录保持不变。

## 8. M5：按需扩展

自动扫榜/浏览器工具需要平台授权、速率预算、SSRF 和版权评审。37 个题材模板按使用频率逐步验收，不以复制完成作为可用完成。向量检索先用 FTS5/结构化事实基线证明有收益，再增加依赖。

封面、更多创作形态、多人协作和云端部署需单独产品与安全方案，不顺带加入 M2。

## 9. 发布门禁与开关

上线顺序：开发 fixture -> 隔离 pilot -> 新书 observe -> 选定规则 enforce -> 小范围存量副本 -> 批量迁移。每一步记录已知限制和退出/恢复条件。

开关粒度按能力与作品，不设计“遇错自动关闭全部治理”的快捷路径。已迁移作品可以从 enforce 降到 observe 放宽创作质量规则，但不能关闭版本校验、事务、锁、路径检查和恢复。

发布前必须同时满足：相关测试绿、故障恢复演练通过、五档视口无重叠、预算可控、许可记录完整、备份可恢复、错误诊断可用。质量盲评未改善时可以只交付工程能力，不宣传效果提升。

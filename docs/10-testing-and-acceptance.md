# Novel Creation 测试矩阵与交付验收标准

文档版本：5.0 | 状态：验收计划，本轮未执行应用构建或应用测试

## 1. 测试分层

| 层级 | 重点 | 工具/方式 |
| --- | --- | --- |
| 静态与契约 | 类型、Zod、哈希、资源链接、兼容 ID | 现有 TypeScript/Vitest、schema fixture |
| 单元 | 门禁、失效、事件归一化、预算、状态机 | Vitest，隔离临时项目 |
| 集成 | 文件/SQLite/任务/跨进程锁/恢复 | 真实 NTFS 临时目录及子进程 |
| API | 幂等、条件请求、授权、SSE、错误 | Hono 请求测试 + 真实服务测试 |
| 前端 | 编辑、IME、乱序响应、错误、焦点 | 组件测试 + Playwright |
| 质量 | 拆书/规则证据、误报、叙事分析 | 人工标注与盲评，不完全依赖模型自评 |
| 运维 | 构建、启动、隔离、备份、恢复、回退 | Windows 演练与产物清单 |

首先记录现有测试基线及既有失败，再评估新改动。不能利用 `--passWithNoTests` 的成功退出声称新能力已经有覆盖。

## 2. 测试数据

准备三个小型授权/自写题材样本，包含至少 15 章人工可核对正文、设定、批准细纲和预期事件。另准备短篇、无细纲、损坏 JSON、重复 ID、同名实体、缺字、跨卷承诺和异常编码样本。

规模样本：1000 章目录、单章 5 万中文字符、10 万实体/承诺记录、长标题/无空格文件名、超过预算的状态卡/上下文、千条任务事件。规模样本可确定性生成，但内容不得当作文学质量评估样本。

参考项目 fixtures 使用固定 SHA，并记录采用及有意偏离上游之处。真实书稿不进入公开仓库，不为测试自动发送到外部模型。

## 4. 事务故障注入

在独立试点子进程注入错误和强制退出，不对正式书稿运行。每个检查点至少覆盖正常恢复与再次恢复两遍，校验文件字节、HEAD、父链、操作回执和投影游标。

| 注入点 | 预期 |
| --- | --- |
| 候选内容写入后、current 指针前 | 已确认版本不丢；未引用新版本不冒充保存成功 |
| operation 已持久、任务尚未启动 | 重启可查询等待/中断状态，不新建重复操作 |
| PREPARED 前后 | HEAD 不变，未完成材料保留或安全清理 |
| 正文已替换、truth 未替换 | 管理读者不见混合状态；恢复 before |
| truth 已替换、章节索引未替换 | 同上，旧快照可恢复 |
| 全部兼容文件已写、HEAD 未替换 | 回到父提交，不推断已成功 |
| HEAD 已替换、journal 未更新 | 认定新提交已发布，补 after 与回执 |
| 已发布、HTTP 响应丢失 | 同幂等键返回原 commitId |
| SQLite 应用中断 | DB 事务回滚/完成其一；按游标重复应用安全 |
| 投影完成、日志终态未写 | 正文成功且游标正确，补终态 |
| 锁租约到期、旧进程恢复运行 | 旧拥有者不得继续发布 |
| 磁盘满、权限拒绝、文件被占用 | 不清除恢复证据，返回明确恢复状态 |
| HEAD/归档损坏 | 封锁写入并给诊断，不自动删除或生成空状态 |

进程 kill 测试不等于断电持久性测试。若对外承诺断电恢复，需要单独验证 fsync、Windows 文件系统与真实故障环境；否则发布说明只承诺已验证边界及备份策略。

## 5. 前端与品牌验收

| 用例 | 通过条件 |
| --- | --- |
| 中文 IME 连续输入 | composition 期间不误保存半个输入、不触发提交 |
| 保存响应乱序 | 较早回执不覆盖新正文，不把 dirty 错标 clean |
| 切换作品/章节/候选 | 旧任务输出不污染新页面，未保存稿可恢复 |
| 生成同时手写 | 生成流独立缓冲，采纳前不改编辑区 |
| 多标签版本冲突 | 明确差异/另存/合并，禁止无提示覆盖 |
| 断网与重启 | 候选可恢复，任务查持久快照，不假报失败/成功 |
| SSE 重复/缺口 | 去重、快照重同步，终态不依赖最后事件 |
| 取消竞争 | cancel_requested 与 cancelled 区分；已提交真实显示 |
| 1440/1024/768/390/320 | 无文字重叠/页面横向溢出，主命令可达 |
| 200% 缩放/长标题 | 内容换行、布局滚动、模态操作不被遮挡 |
| 键盘/屏幕阅读器 | 焦点正确、图标有名称、状态不只靠颜色 |
| 品牌覆盖 | title/侧栏/空态/错误/关于为 Novel Creation；兼容标识/许可保留 |

Playwright 截图覆盖正常、空、加载、失败、冲突、审核过期、提交中和索引落后状态。截图需要人工查看，不能只验证 PNG 文件存在。既有 icon/image 资源应确认加载，无破图与布局位移。

本方案不需要 3D；后续若引入 Three.js/canvas，另加桌面/移动像素非空、场景正确取景及交互移动检查。

## 6. API 与安全测试

- 检查 400/401/403/404/409/412/413/422/428/429/500/503 的语义、结构和敏感信息过滤。
- 请求缺失幂等键、If-Match 或 expectedHead 必须按合同拒绝，不能后台补当前版本使旧操作通过。
- 测试 `..`、URL 双重编码、盘符、UNC、路径大小写、符号链接/junction、ZIP 路径穿越和压缩炸弹。
- 检查跨来源 POST、Host 绕过、CORS、会话、CSRF（cookie 模式）和 SSE 权限；本地地址不等于可信用户输入。
- 对书稿、网页、SKILL.md 注入“读取密钥/执行命令/改系统规则”等文本，必须仍受工具权限约束。
- 模型 key 不出现在响应、日志、浏览器缓存、截图、导出和公开 fixtures 中。
- 其他项目目录不被全书检索、备份和技能加载误扫描；参考库 HEAD 与工作树不因业务请求改变。
- 默认关闭外网/采集仍可本地编辑、读取、导出；GET 不产生付费模型请求。

## 7. 文学质量与规则评估

比较三组：现有宿主基线、只读方法增强、完整候选/合同/审查流程。使用同一题材、细纲和输入约束，记录模型、参数、上下文和用量，避免把换模型的收益归因于整合。

人工评价：设定一致性、目标履约、证据正确、语言自然度、重复表达、情绪推进、作者修改量。评审顺序随机化；可由作者与另一评审独立标注后讨论分歧。

规则指标包括 precision、误报率、遗漏率、不可判定率和作者采纳率。M1 风格建议先 advisory；进入 enforce 的规则必须有独立标注集，建议 precision >=90% 且样本/置信区间可说明。样本不足时保持建议，不用小样本百分比包装可靠性。

“质量更好”与“提交更安全”分别验收。没有真实读者实验就不声称提高真实追读率；不以总分代替正文证据，不对固定 54 节点或统一拖欠章数做普适承诺。

## 8. 性能与预算

每次报告记录 CPU、内存、磁盘类型、Node、浏览器、数据规模、冷热缓存和样本数。非模型操作建议预热后至少 100 次，报告 p50/p95/失败率；大模型时延单独统计。

| 指标 | 初始目标 | 备注 |
| --- | --- | --- |
| 工作区热启动可交互 | p95 <= 2s | 不包含模型生成 |
| 编辑输入响应 | p95 <= 100ms | 包含 IME/长文本场景 |
| 常用列表本地 API | p95 <= 300ms | 分页，避免全量扫描 |
| 候选持久保存 | p95 <= 500ms | 不含前端防抖 |
| 单章提交临界区 | p95 <= 2s | 无模型调用，包含必要持久化 |
| 状态卡 | <=12288 UTF-8 bytes | 另测整体 token 预算 |
| 自动修订 | 默认 1 轮，最大 2 轮 | 不把网络重试偷偷变为新修订 |

预算测试覆盖未知模型价格、返回 usage 缺失、重试可能重复计费、流中断、单日/单任务限额与并发预留。未知费用显示未知，不归零。达到限额后不得继续不受控调用。

## 9. 构建与测试命令

以下在 M0 安装依赖后执行，本轮未执行：

```powershell
Set-Location -LiteralPath 'E:\Desktop\Github\novel'
pnpm build
if ($LASTEXITCODE -ne 0) { throw 'Build failed.' }
pnpm typecheck
if ($LASTEXITCODE -ne 0) { throw 'Typecheck failed.' }
pnpm test
if ($LASTEXITCODE -ne 0) { throw 'Tests failed.' }
pnpm --filter '@actalk/inkos-studio' test:e2e
if ($LASTEXITCODE -ne 0) { throw 'Studio E2E failed.' }
```

E2E 需先确认 Playwright 浏览器依赖、配置的 server/port 和隔离数据目录；不得默认连接正式书库。运行 `test:e2e` 并不自动代表已新增本文所有用例，需逐项核对覆盖。

针对性测试优先复用 Core/Studio 已有 Vitest 目录与命名方式。Python 参考测试仅在隔离开发环境执行，不安装整套依赖到主生产运行环境。

## 10. 文档与发行验收

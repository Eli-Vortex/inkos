## 4. 集成总方案

以现有 InkOS 的 Core、CLI 和 Studio 为唯一宿主，保留 React/Vite/Hono/TypeScript/Zod/SQLite 的技术主干。Oh Story 提供研究、拆书、写作方法和风格检查资产；Webnovel Writer 提供章节合同、审查证据、提交链和追读力方法。

三个仓库不作为三个常驻服务拼接。对作者只呈现一个 Novel Creation 工作台；对数据只保留一条正式写入链；第三方 Dashboard 不另嵌入一套作品状态。

目标闭环：

```text
研究素材 -> 设定与卷纲 -> 已批准细纲 -> 章节合同
       -> 候选稿 -> 审核/局部修订 -> 作者确认
       -> Chapter Commit -> 正式正文与状态 -> 可重建索引
       -> 连续性/追读力反馈 -> 下一章
```

关键决策：

1. 先接只读分析、审查、去 AI 味检查，再接正式正文与状态写入。
2. 候选稿不是正式章节；生成、保存和审核都不能提前推进章节索引或世界事实。
3. CLI、Studio、TUI、Agent、daemon、导入和修复必须共用治理写服务，不能只限制 UI。
4. 以持久化章节计划生成合同；所有审核绑定内容、依赖、规则版本和基线提交，修改后必须重新校验。
5. 多文件原子替换不是跨文件与 SQLite 的数据库事务。通过持久日志、不可变归档、HEAD 发布、读屏障和可重复恢复建立一致性。
6. SQLite 和向量检索只作为可重建投影，不另建第二套权威事实库。
7. 追读力建议必须给出正文证据；“爽点债务”是叙事承诺跟踪，不是以固定章数扣分的通用公式。
8. 中文优先、离线数据优先、作者最终确认。不得以质量优化为由擅自改写或覆盖原稿。

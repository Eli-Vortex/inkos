# Novel Creation 产品定位与品牌更名规范

文档版本：5.0 | 状态：目标设计，尚未修改界面 | 关联：[功能分类](02-feature-catalog.md)、[验收](10-testing-and-acceptance.md)

## 1. 产品定义

**Novel Creation** 是面向中文小说作者的本地优先创作工作台。核心价值是把研究、设定、细纲、正文、审核、正式提交和连载反馈连接成一条可检查、可恢复的创作流程，而不是让作者在三个项目之间搬运文件。

主要用户是独立长篇网文作者、需要保留编辑决策的作者与编辑组合，以及已有书稿需要继续写作的用户。首版按本地单用户设计，不宣称多人实时协同、云端账号体系或自动商业发布已经存在。

作者拥有作品的最终决定权：AI 生成只是候选，评分只是辅助，任何变更都必须能够查明来源、比较差异并保留原稿。

## 2. 产品边界

| 项目 | 定位 |
| --- | --- |
| Novel Creation | 唯一对外产品名、唯一主要工作台 |
| InkOS | 上游工程底座与兼容标识，保留在技术说明和许可证信息中 |
| Oh Story | 创作方法、研究模板、审核与风格资产来源 |
| Webnovel Writer | 合同、提交证据、连续性和追读力方法来源 |

首版必须形成“研究材料 -> 批准细纲 -> 候选稿 -> 审核 -> 作者确认 -> 正式章节”闭环；不得通过嵌入两个第三方 Dashboard 代替统一产品体验。

暂不承诺：无人值守无限连载、保证爆款或收益、通用真实追读率预测、自动取得平台爬取权限、绕过版权限制、自动上传平台或跨作者实时协作。

## 3. 更名范围

标准写法始终为 `Novel Creation`，保留空格与大小写。中文界面中的业务名词可使用“作品”“章节”“审核”等，不另造与其竞争的中文产品名。

| 显示位置 | 目标 | 实施要求 |
| --- | --- | --- |
| 浏览器标题 | `Novel Creation` 或 `章节名 · Novel Creation` | 包括首页、加载、错误和空状态 |
| 侧栏品牌 | `Novel Creation` | 折叠态保留图标及可访问名称，不能挤压导航 |
| 首屏/无作品视图 | 产品名与实际作品操作 | 不新建营销落地页，不写巨大宣传文案 |
| 图标、favicon、安装清单 | 新产品识别资产 | 先审查现有资产，确保商标与许可允许使用 |
| 关于、版本、帮助入口 | 新产品名和准确的版本信息 | 保留上游来源、许可证和源码获取入口 |
| 自有错误包装、通知、启动日志 | 新产品名 | 不篡改需要原样排障的第三方错误内容 |
| 导出默认元数据 | 新产品名 | 作者名、作品名、正文和现有作品元数据不得被替换 |
| 后续截图及使用文档 | 新品牌截图和路径 | 不把修改截图当作已修改应用 |

已核验的起始定位：

- [index.html](../packages/studio/index.html)：当前页面 title 为 `InkOS Studio`。
- [Sidebar.tsx](../packages/studio/src/components/Sidebar.tsx)：当前侧栏含 `InkOS`。
- [App.tsx](../packages/studio/src/App.tsx)：当前首屏含 `InkOS Studio`。
- [server.ts](../packages/studio/src/api/server.ts)：包含用户可见错误包装、启动日志以及上游错误识别正则；三者需要分别判断。

这不是完整替换列表。M0 必须对自有源码、公开静态文件、构建产物和运行页面做覆盖扫描，再区分“显示文案”与“技术兼容/版权声明”。

## 4. 明确保留的兼容项

以下内容不因产品更名而改动：

| 类别 | 保留项 | 原因 |
| --- | --- | --- |
| 包与导入路径 | `@actalk/inkos`、`@actalk/inkos-core`、`@actalk/inkos-studio` | 避免工作区依赖和发布流程失效 |
| CLI 命令 | `inkos` 及当前子命令 | 保持用户脚本兼容；未来别名需单独测试 |
| 配置/运行路径 | `inkos.json`、`.inkos/` | 避免配置丢失和二次初始化 |
| 环境变量 | `INKOS_*` | 不偷偷变更模型配置和根目录解析 |
| 上游技术资产 | `inkos-*` 技能 ID、模块名、Git 历史 | 保持技能注册与升级可追踪 |
| 法律文本 | LICENSE、版权、来源声明 | 更名不改变代码来源或许可证 |
| 用户数据 | 正文、历史日志、作者自定义文本 | 不进行全局内容替换 |

可以新增集中管理的 `PRODUCT_NAME` 等品牌常量，但仅用于自有显示层；不要为了一个名称重构所有包。技术标识、构建版本和产品显示名应分离。

## 5. 版本与来源展示

关于页应区分：Novel Creation 集成版本、上游宿主版本/提交、适配包版本、数据 schemaVersion。文档 `5.0` 不作为应用版本号，当前上游 `1.8.0` 也不等同于已发布 Novel Creation `1.8.0`。

版权来源应在“关于/开源许可”中可访问，避免日常导航仍以 InkOS 充当主品牌。AGPL 宿主与 GPL 参考代码的分发/网络服务义务需要发布前审查，不能因采用 TypeScript 重写就假定相关义务消失。

## 6. 工作方式与模式

作者可选择手写、AI 辅写或按合同生成；三种方式共用候选版本和提交检查。不能要求手写作者先跑一次生成才允许提交。

| 状态 | 用途 | 不允许的行为 |
| --- | --- | --- |
| 未迁移 / off | 旧作品暂走原流程，不宣称拥有提交链保护 | 创建伪造的历史提交证明 |
| 已迁移 / observe | 提示创作质量风险，收集规则误报 | 绕过内容哈希、并发检查、事务与恢复 |
| 已迁移 / enforce | 执行已批准合同和质量门禁 | 无限自动返工、自动覆盖、偷偷降级为旧写入路径 |

已迁移作品不能通过普通开关退回 off。若必须退出治理，需要完整导出、独立恢复工作区和明确的数据兼容计划。

## 7. 用户体验原则

1. 第一屏是实际工作区，不是说明书或营销页。
2. 正文优先，研究、章节树、审核结果与任务进度围绕正文安排。
3. 状态说清“未保存/已保存候选/审核已过期/待确认/已提交”，不把保存提示写成提交成功。
4. 每条质量意见能定位证据、解释来源并记录处理结果；不显示无依据的神秘总分。
5. 批量修订、导出、重置、回退等高影响操作先给影响范围和差异。
6. 网络断开、模型失败和服务重启不应造成编辑缓冲区丢失。

## 8. 更名验收

- 在 1440、1024、768、390、320 像素宽度检查 title、侧栏、空态、错误态与关于页。
- 自有品牌位置不再显示 InkOS；技术兼容、许可证和上游引用保留且列入允许清单。
- 屏幕阅读器能获取完整产品名，移动端不强制把名称压成无法阅读的极小字号。
- 现有配置、包导入、技能 ID、CLI 和作品内容不因更名改变。
- 扫描源码与构建产物后再用 Playwright 检查实际渲染；只通过全文检索不算验收。

实施阶段为 M0，完成状态必须以修改与测试结果记录，不能把本文档的命名决定表述成已经完成更名。

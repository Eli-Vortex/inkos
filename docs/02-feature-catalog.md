# Novel Creation 功能分类与交付清单

文档版本：5.0 | 状态：产品及研发共同基线 | 关联：[路线图](09-implementation-roadmap.md)

## 1. 分类原则

按作者任务分类，不按三个上游仓库分类。每个功能只有一个主入口，同一内容可从上下文跳转查看，但不能生成多份互相竞争的数据。

优先级：P0 为首个安全闭环必需；P1 为连续创作效率；P2 为扩展。里程碑表示首次达到本方案要求，不表示上游完全没有对应能力。表中“已有”仅代表源码中有相关基础，仍需回归。

## 2. 一级导航与页面归属

| 导航 | 二级视图 | 主要对象 | 默认行为 |
| --- | --- | --- | --- |
| 作品 | 列表、详情、最近编辑 | Book、进度、模式 | 恢复上次作品和章节 |
| 研究 | 素材、拆书、题材、榜单记录 | Source、ResearchReport | 先呈现本地材料；外网采集需要明确动作 |
| 设定与大纲 | 世界、角色、卷纲、细纲、承诺 | Settings、Plan、Entity | 显示版本、引用和批准状态 |
| 写作 | 章节树、候选、审核、提交记录 | Chapter、Draft、Review、Commit | 正文工作区为主，审核在同一工作流内 |
| 连载分析 | 连续性、伏笔、承诺、节奏 | Evidence、Promise、Timeline | 点击图表回到具体正文证据 |
| 任务 | 运行中、待确认、失败、历史 | Task、Usage | 以持久任务快照为准 |
| 导出 | 格式、范围、预览、历史 | ExportArtifact | 默认只导出已提交章节 |
| 设置与诊断 | 模型、规则、技能、备份、日志、关于 | Policy、Adapter、Health | 密钥与普通配置分离 |

全局导航不重复放置“所有研究/本书研究”等相似项。作品内视图始终带当前作品上下文；全局任务和设置明确跨作品范围。

## 4. 核心用户流程

### 新书开始

创建作品 -> 选择题材/模式 -> 导入研究资料 -> 编辑设定和卷纲 -> 批准首章细纲 -> 生成或手写候选 -> 审核 -> 确认提交 -> 导出或进入下一章。

每一步都可返回修改；返回修改后只使依赖它的产物失效，不静默删除历史稿件。

### 日常连载

恢复上次工作区 -> 查看未兑现承诺和本章目标 -> 编辑候选 -> 查看差异与审查意见 -> 局部修订 -> 确认 -> 生成下一章计划。不能在作者仍编辑时把流式生成写入同一缓冲区。

### 审核被拦截

跳到证据 -> 修正文稿/明确实体/调整已批准细纲 -> 生成新版本与新审核 -> 再次确认。质量规则在允许时可记录豁免及原因；并发失效、损坏、路径越界和事务恢复问题不可豁免。

### 老书接入

备份 -> 只读预检 -> 生成迁移报告 -> 隔离副本试迁移 -> 建立基线提交 -> observe 校准 -> 作者确认 enforce。M2 先覆盖新书和受控样本，批量存量迁移归 M4。

## 5. 首版不可省略的状态

编辑：加载中、干净、未保存、保存中、保存失败、版本冲突、只读。  
审核：待运行、运行中、通过、需处理、已过期、不可判定。  
提交：待确认、提交中、已提交、失败可重试、恢复中。  
任务：排队、运行、待作者、取消请求中、已取消、完成、失败、中断。  
投影：最新、落后、重建中、失败。

不能以通用“成功/失败”覆盖这些业务差异。完整状态和传输语义见[数据文档](05-data-and-transactions.md)与[API 文档](06-api-contracts.md)。

## 6. 非功能交付要求

- 任何正常或故障路径不得丢失最后一次服务端确认保存的候选稿。
- 正式提交只能对一个明确的基线成功；重复确认不得重复扣预算或再次落章。
- 所有新规则、模板、适配器具有版本和来源；关闭外网能力仍能编辑和导出已有内容。
- 质量、性能、稳定性分别测量，不能以模型输出“看起来更好”替代工程验收。
- 每项交付记录功能 ID、实现 PR/提交、测试用例、截图或运行报告，以及剩余限制。

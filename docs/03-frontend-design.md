# Novel Creation 前端结构与交互优化方案

文档版本：5.0 | 状态：目标设计 | 技术基线：现有 React、Vite、Zustand、Tailwind、lucide-react

## 1. 改造策略

继续使用宿主 Studio，不另建第三方 Dashboard、不整体替换组件库、不引入第二个前端状态框架。先读取并复用现有页面、设计 token 和可访问组件，再增加小说治理需要的状态与操作。

| 现有入口 | 改造职责 |
| --- | --- |
| [App.tsx](../packages/studio/src/App.tsx)、[Sidebar.tsx](../packages/studio/src/components/Sidebar.tsx) | Novel Creation 品牌、导航分组、当前作品上下文 |
| [ChapterWorkspacePanel.tsx](../packages/studio/src/components/ChapterWorkspacePanel.tsx) | 候选稿、细纲、审核、版本比较、提交确认 |
| [Analytics.tsx](../packages/studio/src/pages/Analytics.tsx) | 连续性、承诺、节奏的证据化展示 |

| [DoctorView.tsx](../packages/studio/src/pages/DoctorView.tsx) | 提交链、待恢复事务、投影版本、备份健康 |

## 2. 页面布局

桌面写作页建议采用“导航/章节树 + 正文 + 侧面检查”的工作布局。顶部只保留作品、章节、版本/保存状态和主要动作；任务日志、完整规则解释放到对应详情，不占正文主区。

| 区域 | 建议尺寸与行为 |
| --- | --- |
| 全局导航 | 展开约 208px，折叠约 56px；窄屏抽屉 |
| 章节树 | 约 224px，允许收起；与全局导航不必始终同时展开 |
| 正文 | `minmax(0, 1fr)`，阅读宽度约 720-880px，由容器限制 |
| 审核侧栏 | 约 320-360px；空间不足转为同页标签视图 |
| 工具栏 | 固定图标按钮尺寸 32-40px，触控热区至少 44px |
| 差异视图 | 宽屏左右比较，窄屏逐段行内比较；行号区稳定 |

这些尺寸是待视觉验证的起始约束，不覆盖已有更合适的设计 token。页面区域使用自然布局和分隔线，不把每个部分做成浮动卡片或卡片套卡片。

## 3. 关键页面

### 3.1 作品列表

显示标题、题材、正式章节/字数、最后编辑时间、治理模式、待处理任务；状态不能只靠颜色。列表默认按最近编辑排序，支持搜索、筛选、归档与明确的新建命令。长标题允许换行或省略并可查看全名。

没有作品时直接提供新建、导入操作，不展示产品功能宣传段落。未完成迁移的作品显示状态标签，不冒充已经拥有提交历史。

### 3.2 研究与设定

研究列表显示材料来源、时间、范围、授权标记和分析版本；右侧详情按证据段落组织。正文引用是受控阅读内容，不当作 Markdown 指令执行。

细纲页呈现必达点、限制、角色、时间位置、承诺与批准状态。批准动作记录版本；批准后再编辑需显示“有未批准变更”，旧合同和审核自动标记过期。

### 3.3 写作工作区

同一章以“细纲 / 正文 / 审核 / 历史”视图切换，保留当前滚动位置和未保存状态。正式正文只读查看，编辑产生候选；不能用一个“保存”按钮同时承担保存草稿与正式提交。

候选选择器显示版本、来源（手写/生成/修订/导入）、更新时间和所属基线。提交动作仅针对明确的候选版本，确认框包含：字数变化、状态变更、质量风险、基线提交、尚未完成的索引任务。

### 3.4 审核与分析

审核项目按阻断/警告/建议分组，可按类型、规则、处理状态筛选。每条包含规则名、原文证据、建议、置信状态和操作。误报处理必须记录原因；硬性完整性错误不能在 UI 中“忽略后提交”。

M3 曲线使用已有合适图表能力或经评审的成熟库。所有曲线提供等价列表；点击数据点定位具体章节与引用。缺少数据、模型无法判断、规则不适用分别展示，不画成零分。

## 4. 自动保存与编辑缓冲区

状态机：`loading -> clean -> dirty -> saving -> clean`；失败进入 `save_error`，版本不匹配进入 `conflict`。保存中继续输入时仍保留 dirty，不能被较早响应重置为 clean。

实施规则：

1. 页面按 `bookId + chapterId + draftId` 维护编辑缓冲区、服务端 revision/ETag 和请求序号。
2. 中文输入期间监听 compositionstart/compositionend；输入法组合未完成时不发送自动保存、不触发快捷操作。
3. 输入结束后约 800ms 防抖保存；连续输入设置约 5s 最大等待，但不得强行截断输入法组合。切章前等待最新保存或明确保留本地恢复稿。
4. 保存携带 `If-Match`。同一资源请求串行或合并到最新文本；过期响应只能更新它对应版本的回执，不覆盖新缓冲区。
5. API 返回 `412` 时停止静默重试，读取服务端版本并提供差异、另存候选或人工合并。禁止默认“最后写入覆盖”。
6. 浏览器崩溃恢复可使用 IndexedDB 保存短期本地恢复稿，设置容量/保留期、删除操作和共享机器警示；密钥不得存入。服务端保存回执仍是可靠性承诺边界。
7. `beforeunload` 只能辅助提醒，不能保证异步保存完成；页面关闭后可恢复本地稿不能被描述为已服务端保存。
8. 自动保存不运行付费审核、不自动提交、不更新正式章节统计。

超长文稿处理应先依据现有编辑器能力测试。章节级加载，延迟加载差异与历史；不要为虚拟滚动破坏 IME、选择范围、撤销栈和可访问阅读。

## 5. 流式输出与异步隔离

模型输出展示在独立生成缓冲区，带 taskId、candidateId 和起始基线。作者可继续编辑当前候选，但流式文本不得直接拼入编辑器；完成后作为新候选比较与采纳。

所有请求保存启动时的 book/chapter/draft/revision 标识。切换作品、章节或候选后，旧响应进入对应任务/候选状态，不污染当前页面。AbortController 取消页面订阅不等于取消服务端任务。

SSE 负责进度而非事实权威。前端按事件序号去重，断线重连先获取任务快照，再补事件；缺失事件时显示重同步，不能靠日志数量推测任务成功。

## 6. 提交、取消与恢复交互

点击确认后按钮进入稳定宽度的提交中状态，同一操作使用固定幂等键。浏览器刷新后查原任务/提交，不创建新请求冒险重写。

| 后端结果 | 前端行为 |
| --- | --- |
| `202` | 跳转/关联任务，展示等待状态，不提示已提交 |
| `200/201` 且返回 commitId | 显示正式提交回执并刷新 HEAD |
| `409 STALE_BASE` | 保留候选，提示基线更新，发起重新比较与审核 |
| `412 REVISION_MISMATCH` | 开启编辑冲突处理 |
| `422 REVIEW_BLOCKED` | 定位具体问题与证据 |
| `428 PRECONDITION_REQUIRED` | 前端缺少必要版本条件，保留输入并记录诊断 |
| `503 RECOVERY_REQUIRED` | 暂停正式写操作，提供诊断入口，不建议反复点击 |
| commit 已成功、投影落后 | 显示已提交和“索引更新中”，不能把章节标成失败 |

取消为两阶段：请求取消 -> 服务端确认取消。已进入不可中断发布段时，显示正在完成提交；完成后再提供显式恢复操作，不假装取消成功。

## 7. 视觉与控件规范

- 写作工具采用安静、易扫描的工作台风格；不要大号 hero、营销插画或满屏装饰卡片。
- 继承现有字体和主题能力，正文提供经过验证的中文字体回退。正文字号可选 16/18/20px，界面正文约 14px；不使用视口宽度计算字号。
- 间距基于 4/8px 体系，字距为 0。重复项目/弹窗圆角不超过 8px，除非现有设计系统明确要求。
- 中性背景与高对比文字为主，使用青绿表示操作/通过、琥珀表示警告、红色表示阻断，辅以克制的其他分类色；避免全页单一紫色或深蓝主题。
- 图标采用已有 lucide-react：保存、撤销、重做、比较、下载、设置等使用熟悉图标；不手绘替代已有图标。图标按钮有名称、焦点态与悬停提示。
- 模式使用分段控件，视图使用 tabs，二元配置使用开关/复选框，数值用输入/步进/滑块，选项集合用菜单。
- 有关作品的封面与来源缩略图使用真实或获授权资产；无封面可用现有中性文件占位，不能让图片成为完成工作流的前提。不添加与写作无关的装饰素材。
- UI 中只显示必要业务标签、状态、数据与操作；完整功能说明、样式说明和快捷键说明放文档，不写在主工作区占版面。

## 8. 响应式与可访问性

| 视口 | 预期布局 |
| --- | --- |
| 1440 | 可同时展示章节树、正文、审核；正文不被侧栏压成窄列 |
| 1024 | 默认关闭一个侧栏，审核可抽屉打开 |
| 768 | 正文为主，树和审核以标签或抽屉切换 |
| 390/320 | 单列，工具栏溢出菜单，差异行内展示，弹窗限制高度并可滚动 |

检查 200% 缩放、中文长标题、长英文单词、错误堆栈、无空格文件名。所有 flex/grid 子项按需 `min-width: 0`；不允许按钮文字遮挡相邻按钮，表格在本区域滚动而非撑大整页。

WCAG 2.2 AA 为目标：普通文字对比度至少 4.5:1；键盘可达；模态焦点锁定及返回；图标有 aria-label；保存提示使用节制的 live region；动画尊重 prefers-reduced-motion。质量状态需文字/图标，不能只用红绿。

## 9. 性能预算与验证

在记录 CPU、内存、Node、浏览器版本后建立基线。目标：热启动工作区可交互 p95 <= 2s；编辑输入响应 p95 <= 100ms；本地候选保存 p95 <= 500ms（不含防抖和模型调用）。这些是验收目标，不是已测结果。

以 1000 章目录、10 万实体/承诺记录、单章 5 万中文字符分别测试。目录/报告分页或虚拟化，全文按章读取；禁用无界 store 历史、全量日志订阅和每 token 全页重渲染。

交付需有组件测试、IME/乱序响应测试、Playwright 主流程和五档视口截图。任何 3D/画布扩展另加像素非空和交互验证；本方案不需要新建 3D 场景。
